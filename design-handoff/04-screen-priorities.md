# 04. Screen Priority and Build Order

## Priority model

The product specification defines a full 43-screen system. The build should be sequenced by priority and implementation value.

## P0 screens

These are the highest-priority screens that should be designed and implemented first.

### Learner flows
- Home
- Explore
- Course Detail
- My Learning
- Lesson / Video Player
- Quiz / Result
- AI Tutor
- Portfolio / Career path screens

### Instructor flows
- Instructor Dashboard
- Course Builder
- Course Preview
- Revenue and analytics

### Corporate / admin flows
- Corporate Dashboard
- Employee Management
- Learning Paths
- Admin Dashboard
- Course Moderation
- Payment Management
- User Management

## P1 screens

These are important but should ship after P0 validation.

- Notification center
- Settings screens
- Employer dashboard
- Supplementary analytics views
- Additional portfolio and community screens

## P2 screens

These can be concept screens or low-priority prototype pages.

- Secondary touchpoints
- Additional content experiments
- Non-critical internal utility screens

## Build order recommendation

1. Foundations and tokens
2. Components and states
3. P0 screens in grayscale
4. Apply final color and hi-fi styling
5. P1 screens after sign-off
6. Prototype and stakeholder review

## Note

The recommended Figma approach is to design component libraries and states before full screen creation. This reduces rework and ensures consistency.
